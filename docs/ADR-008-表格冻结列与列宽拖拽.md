# ADR-008: Table 冻结列布局与列宽拖拽

- **状态**: Accepted
- **日期**: 2026-09-30
- **相关代码**: `crates/components/src/table.rs`、`examples/table_demo/src/main.rs`
- **关联**: 路线图 W2（headless分层与组件增强实施路线图.md）；前置 ADR-007（LTO profile）

## 背景

W2 现状核查发现三个事实：

1. `TableColumn.fixed: Option<FixedSide>` 字段与构建器早已声明（含存储测试），但 `view()` 渲染段（280-540 行）对 `fixed` 零引用 —— 声明了但没渲染。
2. 列宽仅支持 `width: Option<f32>` → `Length::Fixed`，无拖拽能力。
3. 垂直虚拟滚动的既定模式是**消息驱动**：demo 用按钮发送 `TableMessage::Scroll(offset)`（offset 由组件钳制），`view()` 中的 `scrollable(body)` 仅承载 ≤ 阈值时的真实滚动；这不是缺陷而是设计，demo 与 table_view.rs 测试均依赖此行为。

iced 0.13.4 无 DOM 级 overflow 联动，双 scrollable（表头横向 + 表体横向）无法在不引入 Task 级 `scroll_to` 的前提下保持同步。

## 决策

### 1. 冻结列 = 三段式布局，同段头体共用一个横向 scrollable

```
Row [
  Column[左冻结表头, 左冻结体]                      ← 无任何 scrollable，永不位移
  scrollable_x( Column[中段表头, 中段体] )           ← 头体在同一横向 scrollable，天然同步
  Column[右冻结表头, 右冻结体]                      ← 同左
]
```

- 头/体横向同步问题通过"**同段头体放进同一个横向 scrollable**"消解，不依赖双 scrollable 同步。
- 垂直方向维持消息驱动虚拟滚动（渲染 `visible_rows()`，无垂直 scrollable），与既有 demo 模式一致。
- 非冻结模式（无 `fixed` 列且未设 `with_horizontal_viewport`）**保持现有渲染路径逐字节不变**，table_view.rs 既有测试即回归底线。

### 2. 列宽拖拽 = 增量消息三元组 + 程序化接口并存

- 状态层：`column_widths: Vec<Option<f32>>`（运行时覆盖）+ `resize_state: Option<(usize, f32, f32)>`（拖拽会话：列索引/上次光标 x/本次会话已用基准）。
- 消息：`ResizeStart(idx, x)` / `ResizeMove(x)` / `ResizeEnd`（表头拖拽条，view_msg 模式接线）与 `ResizeColumn(idx, delta)`（程序化增量）双轨，共用 `resize_column()` 钳制核心。
- 钳制：有 `resizable(min,max)` 按边界；无边界时程序化 resize 兜底 `[40.0, f32::MAX]`。**拖拽条仅对 `resizable` 非空的列渲染**。

### 3. API 兼容策略（v1.0.1 补丁版不动破坏性变更）

- 不引入 `ColWidth` 枚举改 `width` 字段类型（路线图原文方案），改用 `width`（默认宽）+ `resizable: Option<(f32,f32)>`（拖拽边界）两字段表达 `Fixed/Auto/Resizable` 语义 —— 语义等价且零破坏。
- 既有 `view(theme, cell_renderer, on_row_click)` 签名不变；新增 `view_msg(theme, cell_renderer, on_msg: Fn(TableMessage) -> Message)` 承载交互接线（横向滚动、拖拽、行点击统一入口）。
- `TableMessage` 追加变体属于非破坏扩展（下游 match 均有 `_` 臂）。

## 后果

**正面**：
- 冻结列语义落地且零 API 破坏；头体横向同步问题被布局结构消解，无 Task/同步消息负担。
- 拖拽/滚动全部收敛为纯状态计算（`resize_column`/`clamp_scroll_x`/`fixed_partition`），可被 T1/T4 全覆盖，符合 W1"行为层可独立测试"的方向。

**负面**：
- 冻结模式下垂直滚动为消息驱动（无 wheel 原生联动），需要应用层接事件；按钮驱动（demo 现状）与后续 wheel 订阅均可。
- 拖拽条依赖 `mouse_area::on_move`，光标快速移出 6px 拖拽区会中断拖拽（iced 0.13 无全局鼠标捕获），快速拖拽体验受限 —— ADR-009/iced 升级后复评。
- 冻结列未显式宽度时以 100px 兜底（无法自动测宽），文档需明示建议显式宽度。

## 注意事项

- **Bug 定位提示**：如果 ① 冻结列随横向滚动位移 —— 检查该列是否误入中段（`fixed_partition()` 归属）；② 拖拽越界 —— 检查 `resize_column` 钳制分支与 `resizable` 边界透传；③ 头体横向错位 —— 检查中段表头/表体是否仍在同一个 `scrollable` 内；④ 既有表格回归 —— 优先确认走的是非冻结路径（`is_frozen_layout() == false`）。
- 性能预算与基线数字见 `docs/perf_baseline.md`（W3）。
