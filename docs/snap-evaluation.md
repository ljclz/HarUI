# snap 像素吸附评估框架（W8 挂起项实施细则）

> 制定日期：2026-09-30 ｜ 关联：v1.2.0 升级引入的 `Style.snap` 字段（当前全局 `false`）

## 一、snap 是什么

iced 0.14 为所有 quad 渲染（button/container 等 Style）新增 `snap: bool`——
是否把四边形顶点**吸附到物理像素网格**再提交 GPU。

- **开启（true）**：整数坐标的 1px 边框不再落在两个物理像素之间 → 边框更锐利、
  无半透明"糊边"（0.14 的 `crisp` 特性 #2969 同族）
- **关闭（false）**：保持 0.13 的连续坐标渲染 → 动画插值平滑、高 DPI 缩放下无
  "跳动"，但 1px 边框可能出现亚像素模糊

## 二、决策矩阵（哪些组件建议开启）

| 场景 | 建议 | 理由 |
|---|---|---|
| Button / Tag / 静态容器的 1px 边框 | **建议 true** | 平面直角风格（Element Plus）锐度收益最大 |
| Dialog/Drawer 开关动画中的容器 | 保持 false | 动画插值时吸附会产生帧间跳动 |
| Table 斑马纹/行背景 | 可 true | 整行等高矩形，吸附无害且更锐 |
| 阴影（Shadow 有 blur） | 无关 | blur 路径不走 quad snap |
| 高分屏（125%/150% 缩放）Windows | 逐组件实测 | 非整数缩放下吸附可能更糟，必须实测 |

## 三、评估方法（三条路径）

1. **真机像素对比**（首选）：`cargo run -p screenshot_test` 在 100% 与 125% 缩放下
   各截一组，`snap=false` vs `snap=true` 按既有标准比对（AE<100 / SSIM>0.95，
   见 docs/screenshot_test.md）——人工目检边框锐度
2. **组件级开关实验**：先开 Button（border 密集、无动画），确认无回归后按
   `按钮 → 容器 → 表格行` 顺序推进；动画类（Dialog/Drawer/Message）保持最后或不开
3. **CI 基线**：snap 决策定稿后，把选定值写入各组件 StyleSheet 并纳入
   `docs/perf_baseline.md` 同级的"渲染配置基线"，避免后续漂移

## 四、当前状态与触发条件

- 状态：**全局 false**（v1.2.0 迁移保守值，行为与 0.13 一致）
- 触发条件更新（试点后收窄）：AE 像素测量就绪（`scripts/visual_compare.py`
  已就位，snap 对照实测 AE=0.20/SSIM=0.9947——量差在工具可测范围内）或
  业务方明确反馈锐度问题；届时仅改 6 处 button 域 `snap: false → true`
- 不建议动作：在无人工目检的情况下全局翻转——违反 T3 视觉回归纪律

## 五、试点结论（2026-10-10 已执行）

- **技术验证通过**：Button 六种类型 snap=true 在 wasm 画廊实测（2x DPR 截图）——
  编译/渲染/运行时零错误，无布局破坏，无回归
- **视觉收益未定**：1x/2x 截图下锐度差异不可辨（在 AE 像素测量能力就绪前
  无法定论"更好"），按框架纪律回退保守默认 false
- **状态更新**：技术风险已排除，触发条件收窄为"AE 像素测量就绪或业务方
  明确反馈锐度问题"——届时仅改 6 处 `snap: false → true`（button 域），
  container 域维持 false（动画插值安全性）
