# HarUI 技术实现方案

> 基于 iced-rs 0.13 的 Rust 原生通用桌面 UI 组件库
> **定位**：Rust 生态中的 Element Plus，覆盖中后台管理系统 + 桌面应用
> **授权**：核心 60 个基础组件 MIT 开源；6 个 POS 扩展组件 + POS 主题 + 硬件对接作为企业版
> 参考 GPUI Component 架构，但不依赖 GPUI（使用 iced 软件渲染，Win7 兼容）
> 版本: 0.2.0 | 2026-07-18

### 诚实声明

> 本方案不是"100% 复刻 Element Plus"，而是"在 Rust 生态中实现 Element Plus 的视觉规范和组件 API"。
> iced 与 Vue 的本质差异（无 CSS、无 VDOM、无 v-model、无 Teleport）决定了复刻度在 85-95%。
> 详见设计规范.md §复刻度声明。

## 1. 架构概览

### 1.1 核心层

```
┌──────────────────────────────────────────────────────────────┐

│  │  Button / Table / Dialog / Form / Input / ...          │  │
│  └──────────────────────┬─────────────────────────────────┘  │
│  ┌──────────────────────┴─────────────────────────────────┐  │
│  │  主题层 (Theme)                                         │  │
│  │  Color / Typography / Spacing / Shadow / Border / Z     │  │
│  └──────────────────────┬─────────────────────────────────┘  │

│                     (HTTP/WS 通信)                           │
└──────────────────────────────────────────────────────────────┘
```

### 1.2 与 GPUI Component 的差异与借鉴

| 维度 | GPUI Component | HarUI (本方案) |
|------|---------------|----------------|
| 底层框架 | GPUI (Zed 编辑器) | **iced** |
| 渲染方式 | GPU (Metal/DirectX) | **CPU 软件渲染 + GPU (可选)** |
| Win7 兼容 | ❌ | **✅** |
| 组件数量 | 60+ | **66 (全覆盖: 60 基础 + 6 POS)** |
| 设计风格 | shadcn/ui | **Element Plus 100% 复刻** |
| Theme 系统 | JSON + Rust struct | **与 Element Plus 令牌 1:1 映射** |
| 构建工具 | cargo (GPUI Git 依赖) | **cargo + npm (NAPI-RS)** |
| 组件大小 (Button) | ~49KB (button.rs) | **按功能拆分成更小文件** |
| 文档/演示 | Storybook Web | **内嵌 examples/ 目录** |

#### 从 GPUI Component 学到的关键模式

```
模式 1: 组件目录结构
  button/mod.rs    → pub mod 声明
  button/button.rs → 核心实现
  button/toggle.rs → 变体组件
  button/button_group.rs → 组合组件
  → 复杂组件拆分子文件，简单组件单文件

模式 2: Theme 系统架构
  theme/mod.rs           → Theme struct + 统一导出
  theme/color.rs         → 颜色函数库 (35KB!)
  theme/theme_color.rs   → ThemeColor struct
  theme/schema.rs        → 主题 schema 定义 (45KB)
  theme/registry.rs      → 主题注册表
  theme/default-colors.json   → 默认色值 (58KB JSON)
  → 主题是独立的重资产，先搭好再开发组件

模式 3: 组件大小差距
  简单的组件(alert/badge): ~5-10KB
  中等复杂度(checkbox/accordion): ~10KB
  高复杂度(button/dialog): ~27-49KB
  极高复杂度(combobox/code editor): ~45KB+
  
模式 4: 无状态组件模式
  GPUI 使用 RenderOnce + IntoElement trait
  iced 使用 Widget trait + Message enum
  两者都是声明式构建 → API 风格可以借鉴
```

## 3. 主题系统实现

### 3.1 与 Element Plus 1:1 映射

Element Plus 的设计令牌通过 CSS 变量暴露，我们需要在 Rust 中定义对应的结构体。

#### 主题色结构 (theme/color.rs)

```rust

//!   --el-color-primary-light-5: #a0cfff

use iced::Color;
```

### 9.1 实现方式

不依赖外部图标库文件（减少依赖和体积），采用内嵌 SVG 方式：

```rust
// crates/core/src/icon/icons.rs
// 自动生成的图标模块

/// 图标名称枚举 — 映射 @element-plus/icons-vue 的 293 个图标
#[derive(Debug, Clone, Copy, PartialEq)]
pub enum IconName {
    // 方向性
    ArrowLeft,
    ArrowRight,
    ArrowUp,
    ArrowDown,
    // ... (约 50 个 POS 常用图标即可，不需要 293 个)
}

/// 图标组件
pub struct Icon<'a, Message> {
    name: IconName,
    size: f32,
    color: Option<Color>,
    loading: bool,   // 旋转动画
}

impl<'a, Message> Icon<'a, Message> {
    pub fn new(name: IconName) -> Self { /* ... */ }
    
    /// 内嵌 SVG 渲染
    fn svg_data(&self) -> &'static [u8] {
        match self.name {
            IconName::ArrowLeft => include_bytes!("./svg/arrow-left.svg"),
            // ...
        }
    }
}
```

## 11. POS 场景定制（企业版）

### 11.1 与 HarRT 的集成

```rust
// 在示例代码中演示如何将 HarUI 组件与 HarRT 守护进程对接

fn main() {
    // 启动 iced 应用
    iced::application("HarUI POS", PosApp::update, PosApp::view)
        .theme(|_| HarTheme::element_light())
        .default_font(include_bytes!("../fonts/NotoSansSC-Regular.otf"))
        .run()
}

struct PosApp {
    // HarRT 客户端
    harrt: HarRTClient,
    // 购物车状态
    cart: Cart,
    // UI 状态
    dialog_visible: bool,
}

enum Message {
    // 商品选择
    ProductSelected(String),
    // 硬件事件 (来自 HarRT)
    WeightUpdate(f64),
    BarcodeScanned(String),
    // 支付事件
    PayConfirm,
    PaySuccess(PaymentResult),
}

impl Application for PosApp {
    type Message = Message;
    type Theme = HarTheme;
    
    fn view(&self, _window: Window) -> Element<Message> {
        Column::new()
            .push(self.header_bar())     // 搜索栏
            .push(self.main_area())       // 分类+网格+购物车
            .push(self.footer_bar())      // 状态栏
            .into()
    }
    
    fn header_bar(&self) -> Element<Message> {
        Row::new()
            .push(Input::new("搜索商品/扫码")
                .prefix_icon(IconName::Search)
                .on_change(|s| Message::SearchChanged(s))
            )
            .push(Button::new("会员")
                .button_type(ButtonType::Primary)
                .on_click(|| Message::OpenMember)
            )
            .into()
    }
    
    fn main_area(&self) -> Element<Message> {
        Row::new()
            .push(self.category_sidebar())  // Menu
            .push(self.product_grid())      // Grid
            .push(self.cart_panel())        // Table + Keypad
            .into()
    }
}
```

### A.2 GPUI Component 与 HarUI 的关键差异总结

```
GPUI Component 使用 GPUI (Zed 框架):
  - 渲染: GPU (Metal/DirectX 12)
  - 每个文件较大: button.rs 49KB
  - Theme: JSON + Rust 双系统
  - 设计: shadcn/ui
  - Win7: ❌

HarUI 使用 iced:
  - 渲染: CPU (软件) + 可选 GPU
  - 每个文件较小: button.rs ~400行
  - Theme: 纯 Rust struct
  - 设计: Element Plus 100% 复刻
  - Win7: ✅
```
